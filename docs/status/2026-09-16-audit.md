# MUSCA: аудит исходного прототипа и предпосылок

Дата: 2026-09-16. Объём: текущие документы, восемь модулей `musca`, три тестовых
файла, конфигурация локального запуска, GitHub read-back и первичные внешние
источники. Это аудит работающего скриптового стенда, не научная валидация MUSCA.

## 1. Восстановленный контекст и границы

Последовательность задачи: пользователь передал общий и локальный контракт,
исследовательскую и игровую концепции; выбрал оформление документов MUSCA;
затем разрешил продолжить; далее потребовал углублённое исследование и исправление
противоречий. Исходные инварианты сохранены: верхний слой не управляет моторикой,
Bridge выделен, backend заменяем, игра и исследование имеют разные критерии.

Доступная история чата использована как источник требований, не как доказательство
текущего дерева. Перечитаны все проектные Markdown, оба шаблона, исходники и тесты.
Полная переписка и приватные данные в репозиторий не перенесены. Контракт AGENTS
остался без смысловых изменений. В память Codex запись не выполнялась.

## 3. Материальные дефекты и исправления

**F1 · Medium, высокая уверенность — обратная телеметрия не проверялась.**
До исправления `SensorimotorTelemetry(True, 'not a measurement', 'false',
'beacon', 'false')` принималась и превращалась в события сигнала, столкновения
и найденного источника. Причина: аннотации dataclass не выполняют проверку
значений, а непустые строки истинны в условии Python.

Исправлено: `SensorimotorTelemetry.__post_init__` проверяет реальные типы,
неотрицательные числа и Contact enum. `Bridge.events` отвергает объект другого
контракта. Регрессионная матрица отвергает строки и bool вместо измерений,
неправильные признаки и ложный строковый контакт.

**F2 · Medium, высокая уверенность — устаревшее наблюдение принималось за текущее.**
Backend, возвращающий `tick=0` после движения к тику 1, раньше создавал журнал
с противоречащими часами. Теперь tick телеметрии обязан совпадать с сенсорным.
При нарушении эпизод окончательно останавливается, старое разрешение движения
очищается, новый запрос не возобновляет эпизод. Уже выполненный шаг остаётся
в диагностическом журнале; семантические события на его месте не выдумываются.

**F3 · Medium, высокая уверенность — документация отставала от реализации.**
README, charter и CURRENT продолжали утверждать отсутствие кода и выбранной
среды. Обновлены фактическая стадия, команды запуска, локальный объём Python,
статусы ADR и ограничения. Исследовательский протокол теперь явно отличает
существующий скриптовый стенд от отсутствующего научного эксперимента.

**F4 · Low — термин «записанное намерение человека» был слишком сильным.**
Демонстрация использует заданный разработчиком пример, а не запись исследования
участника. CLI и `input_mode` квитанции теперь говорят `predefined_intent`.
Журнал полного произвольного replay пока не загружается через CLI.

Основание повторной петли аудита — реальные F1/F2. После первых 40 проходящих
тестов добавлены регрессии: 43 метода дали 12 отказов (включая подслучаи).
После исправления все 43 проходят. Ошибки не были списаны на среду.

## 4. Требования и фактическая проверка

| Требование | Свидетельство | Результат |
| --- | --- | --- |
| Нет моторных полей в верхнем намерении | Матрица неизвестных полей, координат, направлений и enum | PASS |
| Срок исключителен; отказ очищает старую цель | Тесты `expires_at`, запоздалого/будущего времени, HOLD и частоты намерений | PASS |
| Тело останавливается независимо от backend | Тестовый backend всегда просит east; без разрешения тело стоит | PASS |
| Backend действительно заменяем | Отдельный неподвижный backend проходит тот же runner и не достигает цели | PASS |
| Нет обхода препятствий через runner | Стены блокируют действие, фактический шаг фиксируется как stay | PASS |
| Верхний слой использует только события | Чтение зависимостей, равные наблюдения в мирах с разными скрытыми опасностями | PASS в доверенном локальном коде |
| Предупреждение не равно контакту с вредом | Контрактные и сценарные тесты разных EventKind | PASS |
| Человек может остановиться после свидетельства | Терминальный ввод `go`, `wait`, `quit`; положение остаётся `(2,2)` | PASS для сценария |
| Детерминизм | Отдельные процессы и последовательность эпизодов A → B → A | PASS |
| Ошибка обратного канала не создаёт ложного успеха | Проверки типов, тика, постоянной остановки и журнала ошибки | PASS |
| Файл пользователя сохраняется | Попытка записи поверх существующего файла возвращает код 2 | PASS |
| Реалистичная биология / интерес игроков | Таких опытов не проводилось | NOT RUN |

Программа не является песочницей для недоверенного Python-плагина. Реальный LLM
не подключён: проверен контракт намерений, а не поведение внешней модели.

## 5. Квитанция команд и артефактов

Выполнены: `git status --short --branch --untracked-files=all`, `git rev-parse HEAD`,
`git diff --check`; read-only `gh api` для repository/branches/tree/rulesets/
actions/workflows/actions/runs; GitHub connector для commit, PR и issues.
Desktop Commander: list_devices, get_config, start_process с чтением Git и
запуском тестов. Конфигурация и права не менялись.

Финальные инженерные команды:

```powershell
py -3.14 -m unittest discover -s tests -q
py -3.14 -m musca --demo --mode light --output experiments/results/2026-09-16-light.json
py -3.14 -m musca --demo --mode light_chemical --output experiments/results/2026-09-16-light-chemical.json
git diff --check
```

Локально: **43 tests, OK, exit 0**. Через Remote Desktop Commander после
исправления: **43 tests, OK, TEST_EXIT=0**. В обоих каналах совпали SHA-256:

```text
musca/simulation.py  fbe8f5a4267eb8ecda834685a4e9048ea0e079f0ff1ccdc5cc867fa67dfacb75
musca/contracts.py   3406ec5a6373ec34e0feee16ce57ae6c9f05a2987d99f1c0ce1df6d0daacfb35
```

Локальные JSON-квитанции исключены из Git. Их сохранность после удаления рабочего
каталога не гарантируется. Все восемь runtime-хешей внутри сверены с исходниками.
Неизменность результата проверяется отдельно от меняющегося времени запуска.

| Артефакт | Исход | SHA-256 файла |
| --- | --- | --- |

Хеши связывают текущие файлы, но не заменяют архив исходников или commit.

## 6. Источники, зависимости и варианты «что если»

[Карта свидетельств](../RESEARCH_EVIDENCE.md) содержит первичные статьи,
датированные версии данных, точный upstream commit и три дальнейшие ветки.
Главный результат анализа: опубликованная модель и текущий скриптовый стенд
имеют разные задачи, данные и окружения; перенос результата пока не обоснован.

- Если научный контроллер не даёт выигрыша, игра продолжает использовать более
  подходящий backend; результат опыта сохраняется.
- Если скриптовая сцена неинтересна, расширение до MMO не исправляет отсутствие
  подтверждённой основной петли; сначала меняется сцена и протокол проверки.
- Если отдельная биологическая репликация требует другого Python или большого
  вычислительного бюджета, она получает отдельную среду и план, а не скрытую
  замену окружения этого стенда.

`DRIFT:` глобальный `~/.codex/AGENTS.md` всё ещё содержит правила MUSCA; локальное
разделение создано, глобальная область не исправлялась в рамках проектной задачи.

Отдельный агент финальной проверки не выполнил аудит из-за лимита сервиса.
Его результата нет; итоговое чтение, воспроизведение дефектов и интеграционные
проверки выполнил основной агент. Ранее делегированные исходники и тесты
перечитаны и проверены на общей сборке.

Не проверены: другие ОС, графический интерфейс, доступность научных данных по
учётной записи, реальные нейронные вычисления, внешние LLM, CI и игровой интерес.
