# Локальная сборка пилота GATE-P01

Цель — сохранить исходники, тесты и протокол одним проверяемым снимком до
сбора игровых результатов. Архив не означает выполненный пилот или публикацию.
Формат `musca-local-pilot-v1` нужен для связи результата с точными байтами кода,
пока реализация не представлена отдельным Git commit.

## Создание и проверка

Из корня MUSCA:

```powershell
py -3.14 scripts/pilot_bundle.py freeze --output experiments/results/gate-p01-build.zip
py -3.14 scripts/pilot_bundle.py verify experiments/results/gate-p01-build.zip
```

`freeze` читает только явный список файлов в скрипте: код, тесты, документы
проекта, пустые шаблоны и манифест пилота. Результаты, `.env`, Git-история,
кеши, внешние данные и глобальная конфигурация не входят. Символические ссылки,
выход за корень, пропущенные и чрезмерно большие файлы отклоняются.
Исходные файлы и манифест не редактируются. Существующий архив не перезаписывается.

Архив содержит `bundle.json`: таблицу SHA-256 всех включённых файлов,
идентификатор снимка, хеш манифеста, опорный Python и статус `not_run`.
Идентификатор снимка — SHA-256 канонического JSON таблицы хешей. ZIP имеет
постоянный порядок файлов и служебные даты: одинаковые байты дают одинаковый архив.
В JSON-ответе команды также находится SHA-256 всего ZIP.

Для проверки против ранее записанного внешнего хеша:

```powershell
py -3.14 scripts/pilot_bundle.py verify experiments/results/gate-p01-build.zip --sha256 <64-символьный-хеш>
```

Замените заполнитель реальным значением из квитанции создания. Без внешнего
хеша `verify` подтверждает внутреннюю согласованность, но не автора архива:
злоумышленник может заменить и файлы, и таблицу. Это не цифровая подпись.
Проверка ограничивает размеры, отвергает дубликаты и неожиданные имена;
не извлекает файлы, не запускает код и не делает сетевых запросов.

## Прогон сохранённой версии

1. Проверить доверенный локальный архив и сохранить его внешний SHA-256.
2. Извлечь в новый пустой каталог, не поверх рабочего дерева. Для собственного
   архива, созданного выше, можно использовать PowerShell `Expand-Archive`
   с новым `-DestinationPath`, без `-Force`.
3. В извлечённом корне проверить `py -3.14 --version` и выполнить:

   ```powershell
   py -3.14 -m unittest discover -s tests -q
   py -3.14 -m musca --puzzle --mode light_chemical
   ```

Сам упаковщик не выполняет тесты: `tests=not_run_by_packager` в метаданных
предотвращает ложный PASS. Тестирование именно извлечённой сборки фиксируется
отдельной квитанцией. Python не включён в архив; автоматической установки нет.
Зависимости по-прежнему ограничены стандартной библиотекой.

При настоящих сессиях запускать код из сохранённого снимка. Рядом с каждой
квитанцией хранить идентификатор снимка/хеш ZIP, номер назначения из манифеста,
категориальную анкету и пропуски по [протоколу](PLAYTEST_PROTOCOL.md).
Не менять назначения после результатов. Согласие и срок хранения должны быть
согласованы с участником отдельно: архив их не устанавливает и не подтверждает.

`code_commit=null` в исходном манифесте остаётся честным: идентичность кода
задаётся архивом, не старым базовым commit. `draft_not_run` не меняется
автоматически, поскольку фиксация байтов не равна запуску исследования.

## Ограничения и смена версии

Архив находится локально и исключён из Git вместе с остальными результатами.
Это не внешняя резервная копия; при потере машины он тоже может быть потерян.
Протокол пока разведочный, интерес игроков неизвестен. Старые квитанции
и снимки не переписываются. Изменение цены, подсказок, правил или критериев
потребует новой версии игрового протокола. Изменение списка файлов/формата
архива требует новой версии упаковщика и повторной проверки совместимости.
